# C11「寻应」账号号码 + 密码认证交付与验收

更新日期：2026-10-26（Asia/Shanghai）。本地实现与隔离测试通过；真实账号注册、登录仍待用户验收。此文档替代上一版 Phone Provider 方案。

## 实际身份模型

- 界面接受符合 `^1[3-9]\d{9}$` 的 11 位号码。这个号码仅是账号名；不核验它是否存在或属于注册者，也不作为联系方式或密码找回凭据。账号名先到先得。
- 注册和登录都将同一号码映射为 Supabase Auth 的内部邮箱标识。例如 `13800138000` 映射为 `cn8613800138000@account.xunying.invalid`。`.invalid` 是保留域名，不承担邮件收发。它是 Auth 所需的内部凭据格式，用户无需输入邮箱。
- 调用 Supabase Auth 的 `signUp({ email, password })`、`signInWithPassword({ email, password })`、`getSession()`、`getUser()`、`signOut()`；密码和会话由 Auth 管理，不自建密码表，也不在产品代码保存明文密码。
- 真实用户 ID 仍是 Supabase Auth 返回的 `user.id`，未来数据库所有权应由服务端验证的 `auth.uid()` 决定。号码、内部邮箱和前端状态均不得直接授权商品编辑或删除。旧商品没有因此自动迁移所有权。
- 不启用 Phone Provider，不调用短信 OTP、邮箱 OTP、确认邮件或找回密码接口。本轮不增加微信、QQ、邮箱输入框或商品业务写入。

**限制：**这是未核验的账号名，不能证明手机号归属。用户遗忘密码时，目前没有自助找回方式。项目如需真实校园身份或找回能力，必须另行设计核验与恢复流程。Supabase 服务端是否接受 `.invalid` 内部邮箱尚未通过真实账号创建验证；隔离测试只能证明 SDK 请求结构和界面逻辑。

## 当前 Supabase 配置及用户操作

用现有公开 publishable key 只读读取 `GET /auth/v1/settings`，并在浏览器中复核：`external.email: true`、`mailer_autoconfirm: true`、`disable_signup: false`、`external.phone: false`。按此公开配置，本方案所需的 Email Provider、免邮件确认和注册开关已就绪。公开设置不能证明是否存在自定义 Auth Hook、CAPTCHA 或其他服务端策略。

用户无需保存 Phone 设置，也无需填写截图中的 Twilio 凭证。请保持 Phone Provider 关闭。若真实注册返回无有效 session，先检查 Email Provider、Confirm Email、Auth 错误及日志；不要伪造登录状态。若 Supabase 拒绝 `.invalid` 地址，先记录**错误代码**，此时该内部别名方案未通过真实验收，不要改用他人可收信的真实域名或填入虚假凭证。

Supabase 官方资料：[密码认证](https://supabase.com/docs/guides/auth/passwords)、[Confirm Email 配置](https://supabase.com/docs/guides/auth/general-configuration)、[用户身份与可修改 metadata 的边界](https://supabase.com/docs/guides/auth/users)。

## 运行与人工验收

在项目目录运行已有本地服务：

```powershell
Set-Location 'C:\Users\Lenovo\Documents\ChatGPT\aigc'
node work/local-dev-server.mjs
```

打开 `http://127.0.0.1:8788/login.html`。使用自选测试账号号码和密码；无需向助手提供密码、Token 或完整账号号码。

1. **注册：**填写符合格式的号码、至少 6 位且符合服务端策略的密码与一致的确认密码。预期直接获得 session，显示脱敏账号号码；不收到短信或确认邮件。
2. **刷新：**刷新登录页，去首页再返回。预期会话恢复。可在同源两个标签页检查状态同步。
3. **退出：**点击退出，再刷新。预期保持未登录。
4. **登录：**用同一号码和密码登录。预期成功；错误密码不应显示已登录。
5. **边界：**试填不足 11 位、`128...` 开头或确认密码不一致；应在客户端提示，不发认证请求。
6. **权限：**登录后只读查看商品页面；普通用户商品编辑和删除仍保持停用。无需做真实商品写入来验收认证。

若本地服务未运行，请重新执行上面的命令。保持同一个协议、主机和端口；`localhost` 与 `127.0.0.1` 的浏览器会话存储不共用。
